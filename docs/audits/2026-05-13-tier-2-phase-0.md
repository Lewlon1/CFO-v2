## Headline

**20 of 23 Tier 2 candidates failed verification — i.e., are actually live code.** Only 5 deletions confirmed; one Tier 3 migration backfill confirmed. The session ships a reduced scope and documents the audit drift.

The verification methodology that CODE-MAP relied on (knip + grep) consistently missed three reference patterns:
1. **Dynamic dispatch via library arrays** — analytics functions registered in `PATTERN_LIBRARY` are iterated by `insight-engine.ts`, not imported directly. knip saw the functions as unused exports; they are not.
2. **Type-only imports of route modules** — Next.js route handlers are imported across `lib/hooks/*` and components for their `export type` declarations. The route still serves real requests at the same time.
3. **String-literal fetches inside SWR hooks and onClick handlers** — most "orphan" API routes had real callers, just spelled `fetch('/api/...')` or `useSWR<X>('/api/...', ...)` in components and hooks.

Future audits should grep for `fetch.*['"\``\``][^'"]*api/<path>`, `useSWR.*<path>`, and route-name-as-import-target before flagging an API route as orphan.
