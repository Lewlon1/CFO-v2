# v2.2 Chat Intelligence — Rollout commands

This document covers the manual steps to run AFTER the Phase 7 PR
(scripts + judge harness + persona `--prompt-version` flag) lands on
`main`. None of these are executed by the implementer pass — they
require approval and live Bedrock credentials.

The harness pieces are:

- `cfos-office/scripts/compare-first-insight.ts` — generates V1 and V2
  first-insight responses for one user and writes a markdown diff to
  `cfos-office/tests/onboarding/test-output/compare-first-insight-<userId>-<timestamp>.md`.
  `--judge` appends LLM-as-judge scores per response.
- `cfos-office/tests/onboarding/runner/judge-first-insight.ts` — the
  judge module (Haiku via `utilityModel`, structured output via
  `generateObject` + zod). 8 hard rules + 6 Likert scores. Pass = all
  hard + Likert mean >= 4 + L6 >= 4.
- `cfos-office/scripts/run-personas-v2.ts` — wrapper that adds a
  `--prompt-version v1|v2` flag and forwards everything else to
  `tests/onboarding/runner/cli.ts`, setting
  `CHAT_INTELLIGENCE_V2_FORCE=1` in the subprocess env when v2 is
  selected.

## 1. Cohort flip on staging test users

Always use CFO Staging (`qlbhvlssksnrhsleadzn`), never CFO Prod. Run via
the Supabase MCP `execute_sql` tool, NOT against prod directly.

```sql
-- User Lew 1 (id below is the canonical wave_1 test user).
UPDATE public.user_profiles
SET beta_cohort = 'wave_1'
WHERE id = 'bcfbb511-9b0e-4c13-b566-1ef5b0829fa0';

-- Verify the flip.
SELECT id, display_name, beta_cohort
FROM public.user_profiles
WHERE id = 'bcfbb511-9b0e-4c13-b566-1ef5b0829fa0';
```

The chat-intelligence-v2 feature flag (`cfos-office/src/lib/features/chat-intelligence-v2.ts`)
treats `beta_cohort IN ('wave_1', 'wave_1_5')` as enabled.

## 2. Run persona evals

Sequentially (not in parallel — Bedrock rate limits). The wrapper
script handles the env var; no edits to `cli.ts` needed.

```bash
cd cfos-office

# V1 baseline.
npx tsx scripts/run-personas-v2.ts --prompt-version v1

# V2 (Session v2.2 prompt).
npx tsx scripts/run-personas-v2.ts --prompt-version v2
```

Each run writes results under `cfos-office/tests/onboarding/test-output/`.
Compare summary.json / report.html between the two runs.

## 3. Side-by-side compare for User Lew 1

```bash
cd cfos-office
npx tsx scripts/compare-first-insight.ts bcfbb511-9b0e-4c13-b566-1ef5b0829fa0 --judge
```

Output: `cfos-office/tests/onboarding/test-output/compare-first-insight-<userId>-<timestamp>.md`
with both system prompts, both responses, both tool-call traces, and
(with `--judge`) judge scores for each variant.

## 4. Monitor telemetry for 5 days

Run in CFO Staging Supabase SQL editor (or via MCP `execute_sql`).
Target: < 5 % of v2 first_insight conversations fire the validator.

```sql
SELECT event_type, COUNT(*) AS n
FROM user_events
WHERE created_at > NOW() - INTERVAL '5 days'
  AND event_type IN (
    'first_insight_validator_fired',
    'first_insight_chips_stripped'
  )
GROUP BY event_type
ORDER BY n DESC;
```

Cross-reference against total v2 first_insight conversations in the
window:

```sql
SELECT COUNT(*) AS total_v2_first_insights
FROM conversations c
JOIN user_profiles p ON p.id = c.user_id
WHERE c.type = 'first_insight'
  AND c.created_at > NOW() - INTERVAL '5 days'
  AND p.beta_cohort IN ('wave_1', 'wave_1_5');
```

Fired-rate = first_insight_validator_fired / total_v2_first_insights.

## 5. Git tag (after user approves)

Once the persona evals + telemetry look clean and you're ready to mark
v2.2 as shipped:

```bash
git tag v2.2
git push --tags
```

Also update `cfos-office/package.json` `version` to `"2.2.0"` and add
the corresponding entry to `SESSION-LOG.md` (per CLAUDE.md versioning
conventions).

## Notes on the implementer pass

The implementer pass for Phase 7 added:

- `cfos-office/scripts/compare-first-insight.ts` (new)
- `cfos-office/scripts/run-personas-v2.ts` (new)
- `cfos-office/tests/onboarding/runner/judge-first-insight.ts` (new)
- `cfos-office/tests/onboarding/runner/prompt-version-flag.ts` (new)
- `cfos-office/docs/v2.2-rollout.md` (this file)

The runner's `cli.ts` was NOT edited in the implementer pass — the
runner directory is under a project Read deny rule and the implementer
could not safely read cli.ts to apply an in-place edit. Two options for
the user:

1. **Use the wrapper (`scripts/run-personas-v2.ts`)** — no cli.ts edits
   needed. This is the recommended path.
2. **Inline the flag handler in cli.ts** — add this as the FIRST import
   (above all other imports) in `cfos-office/tests/onboarding/runner/cli.ts`:

   ```ts
   import './prompt-version-flag'  // MUST be the first import
   ```

   The `prompt-version-flag.ts` module parses `--prompt-version`,
   strips it from `process.argv`, sets `CHAT_INTELLIGENCE_V2_FORCE`,
   and prints a banner. After that one-line edit, the runner accepts
   `--prompt-version v1|v2` directly.
