## 0.1 — Post-upload pipeline

**Route file:** [src/app/api/insights/post-upload/route.ts](cfos-office/src/app/api/insights/post-upload/route.ts)

**Critical correction to the Session B plan's mental model:** the post-upload route does NOT
create a chat message. It creates a `conversations` row with `type='first_insight'` plus
metadata, and returns `{ conversationId }`. The actual first-insight *narrative* is generated
later when the user opens that conversation: the `ChatProvider` auto-trigger
([src/components/chat/ChatProvider.tsx:252-254](cfos-office/src/components/chat/ChatProvider.tsx:252)) sends
a system prompt — `"[System: Post-upload analysis triggered. Deliver your first insight.]"` —
and the chat route narrates from `conversation.metadata.first_insight_payload`.

Key fields on the existing flow:
- `conversations.type` = `'first_insight'` (this is the field Session C's cron will filter on, not a non-existent `message_type` on the message)
- `conversations.metadata.first_insight_payload` (V1) or `conversations.metadata.experiment_proposal` (V2)
- Idempotency guard: returns existing fresh conversation if zero-messages row already exists
- Stale typed conversations with messages get marked `completed` first, then a new one is created

**Implication for Phase 3:** the layered Read should pre-compose the message and insert it
directly into `messages` so the auto-trigger guard (`msgs.length === 0`) skips it. Composition
metadata lives on `conversations.metadata.first_read_metadata`. No new column on `messages` —
the table has no `metadata` field and adding one is out of scope.

**Callers:**
- [src/app/onboarding-v2/archetype/archetype-orchestrator.tsx](cfos-office/src/app/onboarding-v2/archetype/archetype-orchestrator.tsx) calls `POST /api/insights/post-upload` after the archetype is shown, then loads the returned conversation.

**Messages table schema** ([001_initial_schema.sql:132](cfos-office/supabase/migrations/001_initial_schema.sql:132) + later alters):
- `id`, `conversation_id`, `user_id`, `role`, `content`, `tools_used`, `actions_created`,
  `profile_updates`, `insights_generated`, `prompt_tokens`, `completion_tokens`, `created_at`,
  `deleted_at`, `anonymised_at`
- No `message_type`, no `metadata` jsonb

its primary use is to clean merchant_keys for *display in the composition prompt* (so the
model sees "POLLO TROPICAL #142" rather than "POS PURCHASE POLLO TROPICAL #142"), not to
correct tool-call inputs.
